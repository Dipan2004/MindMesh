2. ROOT CAUSE ANALYSIS ù WHY ZERO CROSS-DOC EDGES

   builder.py _norm(): casefold + whitespace collapse only
   builder.py _norm_alias(): casefold + strip punct + strip trailing s

   Critical finding:
   Both normalization functions operate PER-CHUNK on a single chunk's
   entity list. There is NO cross-chunk or cross-document resolution.

   For entity X to have source_docs = {doc_A, doc_B}, BOTH must be true:
   a) doc_A chunk extracts entity with EXACTLY the same _norm() key as
      doc_B chunk. E.g. 'FAISS' in doc_A must normalize to the SAME
      key as 'FAISS' in doc_B. This CAN happen (same exact name).
   b) BUT for a cross-doc EDGE, we need a RELATIONSHIP where source is
      from doc_A and target from doc_B ù this requires the LLM to extract
      a relationship spanning two documents IN A SINGLE CHUNK. Since each
      chunk comes from exactly ONE document, this is structurally impossible.

   DIAGNOSIS: The fundamental constraint is per-chunk extraction. Each chunk
   belongs to exactly one doc_id. Relationships can only exist between
   entities co-extracted from the same chunk. No relationship can bridge
   two documents unless a single chunk spans both ù which never happens.
